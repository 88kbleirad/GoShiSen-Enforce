## What changed in CI/tooling (not runtime)

### F-02 (issue #100) — the CLI signing key is approval-gated again

- `release.yml`'s `sign` job declares `environment: signing` (required reviewer
  `88kbleirad`; deployment policies `main` branch + `v*` tag), so a tag release —
  and the dry run — pause for approval before `GH_RELEASE_SIGNING_KEY` is
  resolved (#132). Live evidence: dry run 45163234154 stopped at
  `sign release artifacts (protected environment)` with status `waiting`.
- New structural guard rule `environment-scoped` plus the
  `bad-sign-no-environment.yml` negative fixture: a `sign` job that silently loses
  the environment fails CI (the #125 regression class). `secret-scope` still
  confines the key to `sign` in every scanned workflow.
- The stray, unprotected, secret-less `release-cli` environment was deleted;
  repository environments are `github-pages` and `signing`.
- **Still open in #100:** the key's value must be provisioned into the `signing`
  environment secret (offline backup or a rotation) before the repository-level
  copy can be removed — GitHub never returns a secret value, so it cannot be
  copied from repository scope. Until then signing resolves from the
  repository-level secret *after* the approval click.

### e2e harness — an rc.local boot race can no longer fail the gate (#134)

- `scripts/openwrt-e2e.sh` (v4) gained the explicit daemon start that
  `openwrt-e2e-v6.sh` always had: readiness polls
  `/proc/net/netfilter/nfnetlink_queue` first (authoritative — a bound queue has
  a non-zero peer portid), then the `NFQUEUE bound` log line, and after 300 s
  starts the daemon itself (`setsid … < /dev/null &`, busybox has no `nohup`)
  before re-polling for 120 s. Proven by a forced-race rehearsal (autostart
  removed from a provisioned image): the run logged
  `daemon not ready after 300s; starting it explicitly` and still passed both
  DROP/ACCEPT controls (439.97 s).
- `scripts/e2e-runner.sh` collects `failure-diagnostics.txt` **before** `lab down`
  (the teardown-first order produced an artifact with an empty serial tail and no
  guest state) and adds bounded guest probes: daemon log tail,
  `logread -e goshisen`, `dmesg`, `pidof goshisen` + queue kmods,
  `nfnetlink_queue`, and the `goshisen` nft table. A deliberate-failure run
  produced 3585 B of guest evidence where the old order produced 853 B of nothing.

### CI — network steps are bounded (#135)

- Workflow-level `CURL_BOUNDED` (`--connect-timeout 15 --max-time 300 --retry 3
  --retry-delay 5 --retry-all-errors`) wraps the pinned syft download;
  `APT_BOUNDED` (`-o Acquire::http::Timeout=30 -o Acquire::https::Timeout=30
  -o Acquire::Retries=3`) wraps every `apt-get update/install`.
- Job-level `timeout-minutes` on every job that touches the network or a
  privileged lab (`build` 20, `arm64` 20, `robustness` 30, `package` 30,
  `verify-signatures` 30, `openwrt-integration` 45, `openwrt-integration-v6` 60,
  `integration` 30; `release.yml` already had 15/45/30).
- Two real hangs measured before the fix: `sign + verify release artifacts`
  37m16s (syft download) and `integration` 50+ min (`apt-get update`). After it:
  ~1 min and ~3 min, all jobs green on both runs.

### S-005 govulncheck gates can no longer fail open (security fix)

- The two signing-path gates — `scripts/check-apk-payload-govuln.sh` (apk
  payload) and `scripts/check-cli-archive-govuln.sh` (CLI archives) — each
  carried the same verdict code, and that copy compared
  `"${findings[@]:-}"` against `"${allowed[@]:-}"`; over an EMPTY array that
  expands to one empty word, so `[ "" = "" ]` "matched" and a scan with no
  parsable finding IDs printed `…-GOVULN-GATE-PASS`, reported as "findings are
  allowlisted". Measured against the pre-fix scripts with a stubbed
  `govulncheck`: exit 3 with an empty stream, exit 3 with a finding entry that
  carried no OSV id, and exit 137 (SIGKILL) all PASSed; the fixed gates fail
  closed on all three.
- Both gates now source one implementation, `scripts/lib/govuln-verdict.sh`,
  which keys the verdict off the parsed stream (govulncheck exits 0 under
  `-format json` even when it finds vulnerabilities — `cmd/govulncheck/doc.go`
  in v1.9.0 — so findings arrive on rc 0) and fails closed on an unparsable or
  empty stream, a finding entry without an OSV id, an un-allowlisted finding,
  a missing/non-executable `govulncheck`, and any exit code other than 0/3.
  Findings are printed whether the gate passes or fails.
- The stub outcome matrix in `tests/ci/check-apk-payload-govuln-test.sh` pins
  the rule set; both gate tests keep their real-tool fixtures (current
  toolchain passes, old-Go fixture fails with the blocked IDs, allowlisted IDs
  pass and are reported) and pass locally against govulncheck v1.9.0.

archives are byte-reproducible from the same pin (the `package` job rebuilds them
and compares).
