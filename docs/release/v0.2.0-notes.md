# GoShiSen-Enforce — v0.2.0 Release Notes

Status: release candidate notes (draft). All statements below are backed
by executed evidence recorded in `docs/release/phase11-openwrt-validation.md`
and `/data/phase11-artifacts/`.

## What this release is

v0.2.0 adds OpenWrt packaging, IPv6 enforcement, flow-offload awareness,
and static/reproducible release builds to the v0.1.0 fail-closed NFQUEUE
firewall daemon. The enforcement model is unchanged: the daemon owns one
nftables table (`inet goshisen`) on the forward path and never replaces
firewall4.

## New since v0.1.0

- **OpenWrt package** (`openwrt/`, SDK-built `.apk`): procd init script
  (disabled by default), UCI configuration, fail-closed default policy,
  `prerm` cleanup. The `.apk` is attached to this release (asset
  `goshisen-0.2.0-r2.apk`), sha256 `b4925a60a594159809bd03c10f73843ca3be8ba6748e6343dcc0e1af00a9c2af`.
- **IPv6 enforcement**: the hook is now an `inet` table that queues IPv4
  (queue `100`) and IPv6 (queue `101`) forwarded TCP/UDP; the packet
  parser and policy prefixes support IPv6. Before this release all IPv6
  forwarded traffic bypassed the daemon (fail-open).
- **Flow-offload awareness**: the daemon detects nftables flowtables and
  `flow add @ft` rules, logs a high-severity WARN and exposes
  `goshisen_flow_offload_active` (re-checked every 10 s). It never
  modifies the firewall.
- **Backend error metrics**: parse/panic/send failures are exported as
  `goshisen_backend_errors_total{kind=...}` (previously invisible).
- **Static, reproducible release binaries**: `make build` produces a
  statically linked, `-trimpath` binary; CI asserts static linkage.
- **Reproducible release archives + SBOM** (from v0.1.0→v0.2.0 packaging
  work): `goshisen-linux-{amd64,arm64}.tar.gz`, `checksums.txt`,
  `sbom.spdx.json`; archives byte-identical across rebuilds.

## Install (OpenWrt)

```sh
# verify the artifact checksum first
sha256sum -c checksums.txt
# install (add the release key to /etc/apk/keys to avoid --allow-untrusted)
apk add --allow-untrusted ./goshisen-0.2.0-r1.apk
# enable and start (the package installs disabled and never touches the firewall)
uci set goshisen.main.enabled='1'; uci commit goshisen
/etc/init.d/goshisen enable
/etc/init.d/goshisen start
```

Configure explicit ACCEPT rules **before** enabling: the shipped policy
(`/etc/goshisen/policy.yaml`) drops all forwarded TCP/UDP.

See `docs/openwrt.md` for the full UCI reference, procd usage, recovery,
and upgrade/removal details.

## Upgrade and removal (OpenWrt)

- **Upgrade**: `apk add` the newer `rN` package. The running daemon keeps
  its policy; the hook and queue binding stay in place, so there is no
  fail-open window. Restart the service to run the new binary. User
  configuration is preserved (conffiles); differing shipped defaults are
  written as `.apk-new`.
- **Removal**: `apk del goshisen` runs `goshisen hook cleanup` and stops
  the service, so the app-owned table is deleted and forwarding is not
  left blocked by an orphaned queue rule.

## Known limitations

Stated without softening — all are open follow-ups:

- **Boot-time window**: until the daemon starts (init `START=90`, after
  firewall4) and binds its queues, forwarding is governed by firewall4
  alone — no GoShiSen policy is applied in that window. Only the
  sub-window between hook install and queue bind is fail-closed (queued
  packets have no listener and the kernel drops them). The measured
  hook-install→queue-bind interval on the lab VM was ~170 ms; the
  fw4-start→daemon-start interval was not separately measured, so no
  claim is made about its duration.
- **IPv6 enforcement is verified, stateful ACCEPT is conditional**:
  - Stateless IPv6 allow rules work end to end (verified: full TCP
    request/response completes, HTTP 200) and are fail-closed under the
    default policy (verified).
  - Stateful IPv6 ACCEPT (NEW + ESTABLISHED/RELATED) does **not**
    complete on the verified kernel: the reply arrives INVALID (this
    kernel's `nfnetlink_queue` does not deliver conntrack attributes for
    IPv6) and is dropped by the daemon, so the connection stalls. With
    enforcement on, IPv6 is effectively blocked (never silently allowed).
  - What to do on a dual-stack LAN: use **stateless** IPv6 rules if you
    want IPv6 allowed, or keep IPv6 forwarding blocked/disabled; do not
    rely on stateful IPv6 ACCEPT on this kernel.
- **Flow offloading (software or hardware) lets established flows bypass
  the queue.** The daemon detects offloading, logs a WARN, and exposes
  `goshisen_flow_offload_active 1`, but does **not** disable it.
  Recommended: keep offloading disabled on routers that rely on
  GoShiSen enforcement (`uci set firewall.@defaults[0].flow_offloading='0'`,
  `uci set firewall.@defaults[0].flow_offloading_hw='0'`, `uci commit firewall`).
- **Only x86_64 was verified.** Other architectures (including arm64,
  though archives are built for it) are untested at runtime.
- **`SIGTERM` and `service stop` leave the hook in place** (fail-closed:
  forwarding stays blocked rather than silently allowed). Recovery:
  `/etc/init.d/goshisen start`, or `goshisen hook cleanup` to let
  firewall4 alone govern. `apk del` removes the hook via `prerm`.
- **TCG-measured timings are not performance claims.** All lab numbers
  were taken under QEMU TCG emulation and are indicative only.

## Signing and integrity

- The tag and release are **unsigned** (no signing key configured for
  this project). Integrity is verified by sha256.
- Linux tarballs: `checksums.txt` (attached) lists sha256 for every
  archive; verify before use: `sha256sum -c checksums.txt`. The SBOM
  (`sbom.spdx.json`) is attached for dependency transparency.
- The `.apk` (OpenWrt) is **not signed** with a key trusted by a stock
  OpenWrt. Either add the release public key to `/etc/apk/keys/`, or
  install with `--allow-untrusted` after verifying the sha256 above out
  of band. `--allow-untrusted` skips signature verification and trusts
  whoever served the file; only use it for an artifact whose checksum
  you verified.
- Build provenance: the `.apk` was built from the pinned source commit
  with the OpenWrt SDK 25.12.6 (x86_64 only), reproducibly (two clean
  builds are byte-identical). The tarball binaries
  (`goshisen-linux-amd64.tar.gz`, `goshisen-linux-arm64.tar.gz`) are a
  different build output (different ldflags/version string:
  `goshisen v0.2.0`, static) — these are **not** the same artifact as
  the `.apk`'s binary. sha256:
  - apk `goshisen-0.2.0-r2.apk` = `b4925a60…`
  - apk binary `/usr/sbin/goshisen` = `a00e4a52…`
  - amd64 tarball = `3c2af92c…`, arm64 tarball = `42340ee5…`
- arm64: the arm64 tarball is built and statically verified, but
  **runtime is untested** (only x86_64 was validated).
