# GoShiSen-Enforce v0.2.8 — Release Notes

**Type:** security/hardening release — bounded file reads everywhere operator
input is read, a private policy store with bounded metrics listener, an OpenWrt
`api_token` whose files are created `0600`, authenticated-read opt-ins (D1), and
CI gate re-balancing (D2). **Toolchain: go1.27.4 (unchanged; required minimum
for the apk payload as well as the CLI).**

Tag `v0.2.8` (annotated, **unsigned** — see *Known limitations*) points at
`2bbf53cfda3811ce7278601ac9ac1037cb000b1f`.

## What is new since v0.2.7 (runtime changes)

1. **Bounded file reads (`internal/safefile.ReadBounded`, PR #104).**
   `os.ReadFile` on a non-EOF stream (a character device such as
   `/dev/urandom`, or a FIFO) never returned and grew memory without bound —
   measured ~1 GiB/s RSS in the v0.2.7 anomaly sweep; a policy path pointing at
   such a file hung the daemon/CLI before processing began. The new reader
   rejects non-regular files **without blocking** (O_NONBLOCK open + descriptor
   validation, PR #112) and caps reads at 16 MiB. Applied at every
   operator-input read: config file, CLI `--policy-file`, daemon policy load and
   SIGHUP reload, the policy store (`active.json`, version files), the queue-stats
   procfs reader, and the daemon's pre-start `policy_file` validation
   (PRs #104, #112, #126, #127). Severity assessment: local DoS / CI-hang only —
   the file is operator-supplied and local, so there is no remote vector.
2. **Policy-store permissions tightened + metrics listener bounded (PR #102).**
   The policy store creates its directory `0700` and writes policy/`active.json`
   files `0600` (was `0755`/`0644`) — a second local account can no longer read
   applied policies (CWE-276, gosec G301/G302). The metrics HTTP listener now
   sets `ReadTimeout`/`WriteTimeout` 10 s and `IdleTimeout` 30 s, matching the
   API listener, so a stalled local client cannot hold a connection open.
3. **OpenWrt UCI `api_token` (PR #108, closes #103).** The packaged config can
   set `api_token`; the init script renders it into the daemon config and
   creates/keeps the sensitive files (rendered config and the UCI file) at mode
   `0600` from the first instant (PR #109). The token charset is restricted to
   `A-Za-z0-9._-`; a start with anything else aborts naming the option
   (fail-closed, never shell-evaluated).
4. **Authenticated-read opt-ins, D1 (PR #110, issue #99).** New options
   `require_token_for_reads` and `metrics_token_required` (config file /
   `GOSHISEN_REQUIRE_TOKEN_FOR_READS` / `GOSHISEN_METRICS_TOKEN_REQUIRED` /
   `--require-token-for-reads` / `--metrics-token-required` / UCI). With an
   `api_token` configured:
   - `require_token_for_reads` → `GET /v1/policy` and `GET /v1/policy/versions`
     require the bearer token;
   - `metrics_token_required` → `GET /metrics` requires it;
   - `/healthz` and `/readyz` always stay open;
   - both default **off** (historical behavior unchanged), and setting either
     without a token is a configuration error.

## Upgrade items (what changes for an operator)

- **Misconfigured paths now fail fast instead of hanging.** A non-regular file
  (FIFO, device, directory) or a file over the 16 MiB cap at any of the paths in
  item 1 is rejected with a clear error instead of blocking forever.
- **Authenticated reads are opt-in (D1), default off.** Enabling
  `require_token_for_reads` **breaks** clients that read `/v1/policy` or
  `/v1/policy/versions` without a token — add `Authorization: Bearer …` first
  (same for `metrics_token_required` and `GET /metrics`).
- **The policy store is private to the daemon user.** `policy_dir` is created
  `0700` and its files `0600`; a sidecar that ran as another user and read
  `policy_dir` must be granted access explicitly.
- **Metrics scrapes have a 10 s deadline.** A scrape that takes longer than 10 s
  now fails instead of holding the connection.
- **OpenWrt: `api_token` via UCI, sensitive files 0600.** The token charset is
  restricted to `A-Za-z0-9._-`; anything else aborts the start naming the option.
- **No listener-default change in v0.2.8.** The v0.2.7 semantics still hold: an
  **explicit** `api_port`/`metrics_port: 0` **disables** that listener; an
  **unset** value keeps the defaults (API `127.0.0.1:8080`, metrics
  `127.0.0.1:9090`). If you upgraded from ≤ v0.2.6 and rely on
  `127.0.0.1:9090/metrics`, set the port explicitly.
- **Signing posture:** the CLI release key is repository-scoped and signing is
  not approval-gated (F-02 withdrawn, #125); release tags are annotated but
  unsigned.

## What changed in CI/tooling (not runtime)

5. **Govulncheck is now advisory on PRs, blocking in releases (D2, PR #111).**
   The `robustness` CI job reports findings as a warning + step summary (never
   fails a PR). The blocking gates stay: `release.yml` S-005 binary-mode gates,
   `apk-sign.yml` payload gate, and `release-pin-gate.sh --tag … GATE_S005_CHECKS=1`.
6. **Weekly security sweep (`.github/workflows/security-weekly.yml`).** Mondays
   06:17 UTC plus `workflow_dispatch`; runs govulncheck (source), staticcheck and
   gosec (pinned); opens one deduplicated `[security-scan]` issue on findings.

## Reproduction

Built in the digest-pinned official SDK container
`openwrt/sdk@sha256:a17d6436f7add9207513b6edd0370f5a1aeeceeedf3c9080de8909112892f261`
(`x86_64-25.12.6`) with the official go1.27.4 toolchain. Two independent clean
builds (`A`, `B`) produced byte-identical apk and payload hashes above. Precise
guarantee: **identical hashes on repeated clean builds of the same pin with the
same toolchain and build container** — not across toolchains or a different
OpenWrt SDK tree (the mirror hash is toolchain-specific).

## Known limitations

- **arm64** is still verified only under QEMU TCG (no hardware); the arm64 CLI
  archive is cross-built and its ELF/static properties are checked in CI.
- The D1 opt-ins are covered by unit/integration tests and the CI matrix; they
  have not been exercised on a live OpenWrt router.
- The UCI token-file mode (0600) was verified on a fresh OpenWrt 25.12.6 x86/64
  guest; `uci commit` preserves the mode, but a buggy `uci` tool could reset it —
  the rendered `/var/run` config (0600) is the source of truth.
- Release tags are annotated but **unsigned** (`docs/trust/allowed_signers` is
  committed, but tag signing is not enabled for this release and the pin gate's
  signature check stays opt-in via `GATE_TAG_SIGN_CHECK`).
- The CLI signing key is repository-scoped and signing is **not** approval-gated:
  the `release-cli` environment gate was implemented (#114–#121) and withdrawn
  in #125 because the key's value could not be placed in an environment secret;
  an empty `release-cli` environment remains (no secret, no protection rules).
  See `docs/release/f02-environment-migration.md`.
