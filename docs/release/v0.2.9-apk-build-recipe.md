# v0.2.9 apk build recipe — reconstruction of v0.2.8 and the committed recipe

Status: 2026-11-24, local, no GitHub credential (git-only verification). This
document is the evidence for the change that moves the apk build recipe into the
repository (`scripts/build-apk-release.sh`, `packaging/apk-build/`,
`scripts/check-apk-build-manifest.sh`, `release-pin-gate.sh` step 9). Every
command and hash below was observed on this workstation; the v0.2.8 part is a
reconstruction from preserved scripts and logs, not from a re-run of that
release.

## 1. What existed for v0.2.8, and where it is

The published v0.2.8 apk was built by two ad-hoc scripts that were **never
committed to the repository**; they are preserved on the build host:

| Path | What it is |
| --- | --- |
| `/data/v028-run/sdk-build.sh` | build A (mounts recipe + `/go-host` + `/out`) |
| `/data/v028-run/sdk-build2.sh` | build B (adds `bin/tmp/dl` mounts on `/data`, a disk watchdog, `-e LABEL`) |
| `/data/v028-run/sdk-download.sh` | `PKG_MIRROR_HASH` derivation (zero-hash two-pass) |
| `/data/v028-run/out/compile-{A,B}.log` | the `make … compile V=s` transcripts (12.4 / 12.7 MB) |
| `/data/v028-run/out/{apk,daemon,version,buildinfo}-{A,B}.*` | per-build hashes, payload, version, `go version -m` |
| `/data/v028-run/out/sdk.config` | the SDK config fragment used (now committed as `packaging/apk-build/sdk-x86_64.config`) |
| `/data/v028-run/out/mirror-hash.txt`, `tarball.sha256` | mirror-hash derivation evidence |

Both builds produced the same bytes, and they are the bytes of the published
apk:

Build A used an extra post-`defconfig` step that build B did not:
`./scripts/config -d CONFIG_PACKAGE_{amdgpu-firmware,intel-microcode,amd64-microcode,linux-firmware,iwlwifi-firmware,radeon-firmware}`

apk, so that step is not load-bearing for this recipe; the committed script
therefore does **not** re-run it (the fragment already sets those to `=n`).

The two builds differ in mounts and safety rails only:

| Difference | A (`sdk-build.sh`) | B (`sdk-build2.sh`) |
| --- | --- | --- |

| compile log | captured via container stdout | written to `/out/compile-<label>.log` inside the container |

## 3. The one recipe change — and the part that cannot be reconstructed

The committed `openwrt/Makefile` at `v0.2.8^{}` carries
`PKG_BUILD_DEPENDS:=golang/host`. The release builds used a **local copy** of the
recipe with that dependency disabled, so the SDK never built Go from source
inside the container (that closure is ~2 GB and was the first ENOSPC point on
this 16 GB host).

Evidence that it was disabled, from the preserved log:

```
$ grep -E '^time: ' /data/v028-run/out/compile-A.log
time: package/feeds/base/gpio-button-hotplug/compile#1.24#0.38#1.56
time: package/toolchain/compile#1.17#0.42#1.47
time: package/feeds/base/linux-firmware/compile#20.00#4.20#14.52
time: package/feeds/base/nu801/compile#0.73#0.29#0.92
time: package/kernel/linux/compile#133.73#54.99#169.72
time: package/feeds/base/jansson/compile#4.65#2.18#6.32
time: package/feeds/base/libmnl/compile#10.78#2.29#13.81
time: package/feeds/base/libnftnl/compile#12.80#5.87#16.33
time: package/feeds/base/nftables/json/compile#23.63#4.23#22.55
time: package/feeds/goshisen/compile#27.55#4.46#14.59
```

There is **no `golang/host`, `golang1.27` or bootstrap target** in that list —
only the package's own dependency closure (kernel, nftables, libmnl, libnftnl,
jansson, linux-firmware, toolchain). The only `golang*` lines in the log are the
package's module downloads:
`go: downloading golang.org/x/{sys v0.49.0,net v0.62.0,sync v0.20.0}`.

**Not reconstructable:** the bytes (and path) of that local recipe copy. It was
not preserved — a filesystem search for a `Makefile` containing
`PKG_NAME:=goshisen` with a commented/removed `PKG_BUILD_DEPENDS:=golang/host`
line under `/data`, `/tmp` and `/home` found none (only the repo's own tree and
unrelated historical feeds). So the *exact* local copy is unknown; what is known
is (a) the documented statement in `docs/release/v0.2.8-build-evidence.md` §2
that the dependency was "commented out for the local run only", (b) the log
evidence above that it was not built, and (c) that the rest of the recipe must
have been the committed one, since the produced apk is the published apk signed
from that dispatch. The committed overlay
(`packaging/apk-build/no-golang-host.patch`) therefore reproduces the *effect*
that was documented and logged, not a byte-identical copy that no longer exists.

Also not recoverable: the intended `REPO_TREE` argument both scripts received
(the recipe copy, per the previous paragraph), and whether A and B shared it.

## 4. Recipe differences vs `openwrt/Makefile` at the v0.2.8 tag

Word-level diff of the committed recipe between the v0.2.8 tag and `main`:

```
$ git diff --stat 'v0.2.8^{}'..main -- openwrt/
 openwrt/Makefile | 28 +++++++++++++++-------------
 1 file changed, 15 insertions(+), 13 deletions(-)
$ git diff --stat 'v0.2.8^{}'..main -- openwrt/files/     # empty
```

So the differences are, in words: `PKG_VERSION` 0.2.8 → 0.2.9; comment text
about which release the pin tracks and when the pin PR lands;
`PKG_SOURCE_VERSION` 192eba70… (the v0.2.7 tag commit) → 2bbf53cf… (the v0.2.8
tag commit); `PKG_MIRROR_HASH` b74830be… → c58a2dd5…. **No executable line
differs**: `PKG_NAME`, `PKG_RELEASE`, `PKG_BUILD_DEPENDS`, `STRIP`,
`Build/Compile`, the install section and every lifecycle hook are unchanged, and
`openwrt/files/**` (init scripts, config, policy, lifecycle helper — the content
that ends up inside the apk) is byte-identical.

The committed recipe change for this release is therefore exactly:

1. `packaging/apk-build/no-golang-host.patch` — comments out
   `PKG_BUILD_DEPENDS:=golang/host` (applied to a scratch copy by the build
   script; the committed `openwrt/Makefile` keeps the dependency, which is what
   the SDK digest and the feed pins were reviewed against);
2. `packaging/apk-build/sdk-x86_64.config` — the previously untracked SDK
   config fragment.
