# v0.2.9 apk build recipe — reconstruction of v0.2.8 and the committed recipe

Status: 2026-11-24, local, no GitHub credential (git-only verification). This
document is the evidence for the change that moves the apk build recipe into the
repository (`scripts/build-apk-release.sh`, `packaging/apk-build/`,
`scripts/check-apk-build-manifest.sh`, `release-pin-gate.sh` step 9). Every
command and hash below was observed on this workstation. The v0.2.8 part is a
reconstruction from preserved scripts and logs, and §8 then re-runs it: the
committed recipe reproduces the published v0.2.8 unsigned apk byte-for-byte.

## 3. The one recipe change — and the part that cannot be reconstructed

The committed `openwrt/Makefile` at `v0.2.8^{}` carries
`PKG_BUILD_DEPENDS:=golang/host`. The release builds used a **local copy** of the
recipe with that dependency disabled, so the SDK never built Go from source
inside the container (that closure is ~2 GB and was the first ENOSPC point on
this 16 GB host).

Evidence that it was disabled, from the preserved log:

```
$ grep -E '^time: ' /data/v028-run/out/compile-A.log
time: package/feeds/base/gpio-button-hotplug/compile#1.24#0.38#1.56
time: package/toolchain/compile#1.17#0.42#1.47
time: package/feeds/base/linux-firmware/compile#20.00#4.20#14.52
time: package/feeds/base/nu801/compile#0.73#0.29#0.92
time: package/kernel/linux/compile#133.73#54.99#169.72
time: package/feeds/base/jansson/compile#4.65#2.18#6.32
time: package/feeds/base/libmnl/compile#10.78#2.29#13.81
time: package/feeds/base/libnftnl/compile#12.80#5.87#16.33
time: package/feeds/base/nftables/json/compile#23.63#4.23#22.55
time: package/feeds/goshisen/compile#27.55#4.46#14.59
```

There is **no `golang/host`, `golang1.27` or bootstrap target** in that list —
only the package's own dependency closure (kernel, nftables + libnftnl/libmnl,
jansson, `nu801`, `gpio-button-hotplug`, `linux-firmware`, toolchain). The only
`golang*` lines in the log are the package's module downloads:
`go: downloading golang.org/x/{sys v0.49.0,net v0.62.0,sync v0.20.0}`.

**Not reconstructable:** the bytes (and path) of that local recipe copy. It was
not preserved — a filesystem search for a `Makefile` containing
`PKG_NAME:=goshisen` with a commented/removed `PKG_BUILD_DEPENDS:=golang/host`
line under `/data`, `/tmp` and `/home` found none (only the repo's own tree and
unrelated historical feeds). So the *exact* local copy is unknown; what is known
is (a) the documented statement in `docs/release/v0.2.8-build-evidence.md` §2
that the dependency was "commented out for the local run only", (b) the log
evidence above that it was not built, and (c) that the rest of the recipe must
have been the committed one, since the produced apk is the published apk signed
from that dispatch. The committed overlay
(`packaging/apk-build/no-golang-host.patch`) therefore reproduces the *effect*
that was documented and logged, not a byte-identical copy that no longer exists.

Also not recoverable: the intended `REPO_TREE` argument both scripts received
(the recipe copy, per the previous paragraph), and whether A and B shared it.

## 4. Recipe differences vs `openwrt/Makefile` at the v0.2.8 tag

Word-level diff of the committed recipe between the v0.2.8 tag and `main`:

```

 1 file changed, 15 insertions(+), 13 deletions(-)
$ git diff --stat 'v0.2.8^{}'..main -- openwrt/files/     # empty
```

So the differences are, in words: `PKG_VERSION` 0.2.8 → 0.2.9; comment text
about which release the pin tracks and when the pin PR lands;
`PKG_SOURCE_VERSION` 192eba70… (the v0.2.7 tag commit) → 2bbf53cf… (the v0.2.8
tag commit); `PKG_MIRROR_HASH` b74830be… → c58a2dd5…. **No executable line
differs**: `PKG_NAME`, `PKG_RELEASE`, `PKG_BUILD_DEPENDS`, `STRIP`,
`Build/Compile`, the install section and every lifecycle hook are unchanged, and
`openwrt/files/**` (init scripts, config, policy, lifecycle helper — the content
that ends up inside the apk) is byte-identical.

The committed recipe change for this release is therefore exactly:

1. `packaging/apk-build/no-golang-host.patch` — comments out
   `PKG_BUILD_DEPENDS:=golang/host` (applied to a scratch copy by the build
   script; the committed `openwrt/Makefile` keeps the dependency, which is what
   the SDK digest and the feed pins were reviewed against);
2. `packaging/apk-build/sdk-x86_64.config` — the previously untracked SDK
   config fragment.

## 5. The committed recipe — what a release run does now
scripts/build-apk-release.sh --commit <pin-commit> --go-root <verified go1.27.4> \
  --label A --out <out> --work <scratch-A> --canonical-name
scripts/build-apk-release.sh --commit <pin-commit> --go-root <verified go1.27.4> \
  --label B --out <out> --work <scratch-B>
scripts/check-apk-build-manifest.sh --manifest <out>/build-manifest-A.json \
  --compare <out>/build-manifest-B.json --apk <out>/goshisen-<ver>-r<rel>.apk
```

It `git archive`s the commit, applies the committed overlay to a **scratch**
copy, folds in the committed SDK config, verifies the pinned Go tarball/bin
hashes, derives or verifies `PKG_MIRROR_HASH`, uses the SDK digest pinned in
`apk-sign.yml`, asserts inside the container that the apk is unsigned
(`apk verify` → `UNTRUSTED signature`, because OpenWrt 25.12 apk v3 is an ADB
container, not a tar), and writes `build-manifest-<label>.json`.
`scripts/check-apk-build-manifest.sh` re-derives every manifest claim from the
commit; `scripts/release-pin-gate.sh --manifest FILE` (or `GATE_MANIFEST=FILE`)
runs it as step 9 of the release gate, against the tag commit.

| Artifact | This run (label C) | v0.2.8 build outputs on disk |
| --- | --- | --- |

| payload sha256 / size | `2495b30ff0a3ce5c8a1844c4820b4c769ed5ad20c950062cf11c88f22435fa2e` / 7,848,096 B | `daemon-{A,B}.bin` — `cmp` **IDENTICAL** |

`b97f0da4…` is exactly the `expected_sha256` the maintainer's `apk-sign.yml`
production dispatch carried for v0.2.8 (`docs/release/v0.2.8-build-evidence.md`
§2/§3), i.e. this run rebuilds the pre-signing artifact that became the published
`signed` apk `7df0ca8d…` (3,286,062 B).

Two honest notes:

- signing is **not** a pure append: the first 3,286,014 bytes of the published
  signed apk are *not* a prefix of (and do not hash to) the unsigned artifact
  (`head -c 3286014 … | sha256sum` → `85534436…`, `cmp` differs at byte 20), so
  the unsigned hash — not a prefix relation — is the anchor for a pre-signing
  build. The earlier v0.2.8 note "the difference is the appended apk v3
  signature block" is a size description, not a byte-layout claim.
- this reproduction depends on the v0.2.8 *era* inputs (version `0.2.8`,
  `PKG_RELEASE=1`, the v0.2.8 pin and mirror hash). For v0.2.9 the equivalents
  are the v0.2.9 tag commit and its derived mirror hash, which only exist after
  the maintainer tags — exactly the post-tag pin PR step.

## 9. Proof run — fresh-VM smoke and a fail-closed upgrade

Guest: pristine no-daemon image `/data/x86-lab/v027-no-daemon.img`
(sha256 `b77eec31f8a6afc380a19854b396ea63d61bf39b45e17821181824244c7f0c22`),
OpenWrt 25.12.6 x86/64, kernel `6.12.112`, `nftables v1.1.6`,
`apk-tools 3.0.5`, TCG (`qemu-system-x86_64`). Lab: `scripts/openwrt-lab.sh` +
`scripts/openwrt-console.py`, LAN client in netns `gsh_owrt_lan` at `10.0.3.2`,
marker served from the host at `127.0.0.1:8099` (aliased `10.0.2.2`). Driver:
`run-029-smoke.sh` in this work's handoff (adapted from the v0.2.8 drivers; the
in-repo `scripts/openwrt-e2e.sh` owns the enforcement-e2e surface, so the driver
is not committed here).

Phase 1 — the **unsigned** test apk, installed with `--allow-untrusted`
(pre-release label only):

| Check | Result |
| --- | --- |
| install (`apk add --no-network --allow-untrusted`) | installed `goshisen-0.2.9-r99` |
| guest payload sha256 | `ba8183b109e7ac82a4fc73fe0ed140bd4c3dafa72fbfba0450bab70abc908804` — equals the built payload |
| guest `--version` | `goshisen 0.2.9` |
| queues | `100` and `101` bound (non-zero peer portids) |
| `default_action: DROP`, no rules | 3/3 probes blocked |
| DROP/ACCEPT paired controls | 2/2 allow probes returned the marker; deny probes still blocked |
| SIGKILL respawn (procd) | new daemon, queue rebound, allow still passed |
| `apk del goshisen` cleanup | `inet goshisen` table gone, queue gone |

Phase 2 — **upgrade from the published signed v0.2.8 apk** to the unsigned test
apk with `default_action: DROP` and continuous probes that must never pass:

| Check | Result |
| --- | --- |
| install of the published v0.2.8 apk | `apk verify --keys-dir /etc/apk/keys` → `OK`, `apk add --no-network` **without** `--allow-untrusted` |
| pre-upgrade deny probe (positive control) | blocked |
| upgrade (`apk add --no-network --allow-untrusted` of the test apk) | daemon after upgrade `goshisen 0.2.9` (new pid), queues rebound (`100=<new pid>`) |
| probes across the stop/start window | **21 probes: 0 returned 200, 21 returned 000** (blocked) — no fail-open |
| post-upgrade deny probe | still blocked (the DROP policy survived the restart) |
| teardown | no QEMU, no netns, no TAP left |

Honest limits: under a DROP policy each probe burns its full connect/max timeout,
so the sample is ~21 probes over ~2 minutes (≈1 per 6 s), not the 0.2 s cadence
of the v0.2.8 availability test (which used an ACCEPT policy and measured
availability, 117/118 probes 200). This test measures the *fail-closed* property
— that nothing leaked while the package was stopping and starting — not
availability. It does not exercise the signed v0.2.9 artifact (none exists), a
long soak, or arm64.
