## Verifying and installing the signed package

APK public trust anchor (full SHA-256 of DER SPKI):
`542bb7ae9058fee9b4d37ed30b0af44f234ea7cb8866daa1ffc71a7bc37c839d`.
Cross-check this fingerprint from a second source (e.g. the repository
`keys/goshisen-apk.pub.pem` + the custody record in
`docs/release/apk-signing-key-custody.md`).

Install the anchor into the OpenWrt trust store and install the package
**without** `--allow-untrusted`:

```sh
# on the router/VM (as root)
mkdir -p /etc/apk/keys
# fetch the anchor (or copy from a trusted medium)
wget -O /etc/apk/keys/goshisen-apk.pub.pem \
  https://raw.githubusercontent.com/88kbleirad/GoShiSen-Enforce/v0.2.4/keys/goshisen-apk.pub.pem
openssl pkey -pubin -in /etc/apk/keys/goshisen-apk.pub.pem -outform DER | sha256sum
# must print: 542bb7ae9058fee9b4d37ed30b0af44f234ea7cb8866daa1ffc71a7bc37c839d

# verify the package signature with apk (expected: OK)
apk verify --keys-dir /etc/apk/keys /path/to/goshisen-0.2.4-r1.apk

# install (signature verified by apk; no --allow-untrusted)
apk add /path/to/goshisen-0.2.4-r1.apk

# check the installed binary + its checksum
apk list --installed | grep goshisen
sha256sum /usr/sbin/goshisen
/usr/sbin/goshisen --version   # => goshisen 0.2.4
```

The release's `checksums.txt` lists the CLI archive hashes (signed by the
release step). The **signed APK** asset is
`goshisen-0.2.4-r1.apk` with sha256
`8ec8ff6c4147eecc7c87933177d6b42a9abb906cb346673c72ef6f93214118f4`
(production-signed; gate provenance records it). The
pre-signing apk (built from the same commit, same recipe) has sha256
`eb975a192fff9f2240109bd8fdd53304d951c0cbcde2b071a0a9b5fdb1b02e20`;
the difference between the two is exactly the appended apk v3 signature
(control block + signature), which apk-tools verifies. Both contain the
same daemon binary: sha256
`1feebeba3e6df031a7384384a85fcd154fbef4a0084ad5bd9e0079fbeb9e1894`
(static x86-64 ELF, `--version` → `goshisen 0.2.4`).

**Reproducibility statement:** the apk container embeds a build timestamp
(`version.date`, from the source archive's commit time), so two apk
builds at different wall-clock times produce different *container* sha256
even for byte-identical payloads. The v0.2.4 pin was built from the tag
commit in the official SDK container (`openwrt/sdk:x86_64-25.12.6`;
CI now pins it by digest — `openwrt/sdk@sha256:a17d6436f7add9207513b6edd0370f5a1aeeceeedf3c9080de8909112892f261`),
source tarball `goshisen-0.2.4.tar.zst` sha256
`0d29ef8b7a6da381f6287b5138e64eb49e828182dc221026d288c64dd1797172`.
Guaranteed: two clean builds from the same pin in the same official SDK
produce the same container hash today. Not guaranteed: byte-identity
across different toolchains, times, or non-official environments (the
host SDK produces a different tarball hash `0f60eeb3…` for the same pin;
container-derived hash is authoritative).

## Which public key is which

- **APK anchor** (used to verify the package): `keys/goshisen-apk.pub.pem`
  — an EC (P-256) public key, DER-SPKI SHA-256 fingerprint
  `542bb7ae9058fee9b4d37ed30b0af44f234ea7cb8866daa1ffc71a7bc37c839d`.
  Install it at `/etc/apk/keys/goshisen-apk.pub.pem` on OpenWrt.
- **CLI release key** (used to verify the tarballs/checksums/SBOM):
  the `public_key.pem` asset attached to this release — an Ed25519
  public key produced by the release signing step. It is **NOT** the APK
  anchor and cannot be used to verify the package; the two keys are
  distinct and never interchanged (verified by the signing gate).

## Known limitations

- **Stateful IPv6 (issue #5):** stateful IPv6 ACCEPT is **verified
  working** on kernel 6.12.112 with the canonical bidirectional
  `ESTABLISHED/RELATED` rule pattern (see
  `docs/release/issue-5-investigation.md`). Stateless IPv6 ACCEPT is
  verified; other kernels remain untested (fail-closed by construction).
- **Other architectures (issue #7):** x86_64 and aarch64 (armsr/armv8,
  QEMU TCG) are verified; other OpenWrt targets are untested.
- **LuCI (issue #8):** a LuCI frontend is proposed (design doc) but not
  implemented.
- The daemon binary's `--version` prints `0.2.4` (no `-r1` suffix; the
  package release suffix is an apk concept).
- QEMU TCG emulation only for aarch64 (no physical hardware claim);
  flowtable offload hit counters are TCG-zero (bypass impact not
  observable in the lab).
- **Boot-guard:** the package ships `goshisen-boot` (START=12) which
  drops forwarded traffic in the app-owned table before the daemon
  replaces it — the pre-daemon window is fail-closed (measured ~170ms
  in v0.2.1). `apk del` runs the hook cleanup.
- **apk checksum:** the signed apk's sha256 is recorded in this body and
  in the signing gate provenance; `checksums.txt` intentionally contains
  only the CLI archive hashes (it carries a detached release signature
  that would be invalidated by editing).
