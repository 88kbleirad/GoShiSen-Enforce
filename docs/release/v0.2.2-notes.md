## What this release is

v0.2.2 is the first release that ships the Phase 14.2 stack: it carries
the signing/provenance tooling and production trust anchor, the runtime
flow-offload enforcement/observability features, and the reproducible
privileged e2e/verification infrastructure. It also includes the
readiness shutdown-race fix and the OpenWrt downgrade-cleanup package
changes (the latter only in the repo's package tree — see the versioning
decision; the pinned package source is unchanged).

## Highlights (runtime/behavior)

- **Artifact signing + provenance** — release artifacts are Ed25519
  raw-signed (`*.sig`, `*.sig.pem`), with per-artifact
  `*.provenance.json(.sig)` + `provenance-index.txt.sig` and a committed
  production trust anchor (`keys/goshisen-release.pub.pem`, fingerprint
  `24215e016621925215dec0ad6ea14ac74253a4e97249a973e89d649a2217cca0`).
  `release.yml` now runs `release-sign.sh` on tag push (fail-closed:
  missing/mismatched secret aborts before signing; key trap-removed;
  still DRAFT-only, never auto-publishes). The verifier
  (`verify-signatures.sh`) is the enforcement gate.
- **Flow-offload enforce-mode disable** — new `offload_policy=enforce`:
  the daemon detects flow offloading (state machine disabled/enabled/
  failed/unknown) and **disables** it (nft handles → flowtables in one
  transaction) with fail-closed behavior; `allow_bypass` is a diagnostic
  escape hatch (enforce-only). New CLI `offload status` / `offload
  disable`; 10 s watchdog re-detects and re-disables after `fw4 reload`.
- **Flowtable bypass observability** — `offload observe` reports state +
  per-flowtable hit counters (from the flowtable `counter` statement)
  with an absent/zero-hit/positive/unknown model; metrics
  `goshisen_flowtable_hits_packets` (+`_available`). Zero-hit ≠ disabled
  (this is a measurement instrument; QEMU TCG offloads 0 packets, so a
  positive-hit proof requires a hardware-capable environment).
- **Readiness shutdown-race fix** — `internal/app`: `ready` is cleared on
  every exit path (`defer d.ready.Store(false)`); a fast shutdown can no
  longer leave `ready=true` after `Run` returns.
- **OpenWrt downgrade cleanup** — package `prerm` now unconditionally
  removes package-owned rc.d links; apk v3 does not run the old
  package's pre-deinstall on downgrade, so the documented safe path is
  pre-downgrade `goshisen-boot disable` + a fixed-path `unlink` rescue.
  (Shipment of this in the built `.apk` depends on the package source
  pin — see "Versioning / package decision".)

## Highlights (operational / test / CI)

- **Reproducible privileged NFQUEUE e2e runner** (`scripts/e2e-runner.sh`):
  typed preflight → environment manifest → pinned-image provisioning →
  boot → e2e → trap teardown → failure artifacts; exit codes 0/1/3
  (BLOCKED)/4/5; `E2E_PREFLIGHT_ONLY=1` stops after READY; boots the
  provisioned image (`OPENWRT_IMAGE=$IMAGE`), tears down under the same
  privilege as boot.
- **Hermetic preflight fixtures**: environment-view injection
  (`real_env` / `E2E_PREFLIGHT_FIXTURE`); unit tests need no host tooling.
- **Environment manifest + diagnostics** (read-only, written before
  preflight so blocked runs still record env); failure artifacts
  collected.
- **arm64 runtime verification** — cross-build + static-ELF CI job
  (`arm64`), qemu-user smoke, and live OpenWrt `armsr/armv8` aarch64
  QEMU TCG evidence (bind/readiness, ACCEPT/DROP verdicts, atomic reload,
  restart/graceful shutdown, offload enforce/observe).
- **Lab hardening / port gate 5555/2222 only**; e2e reload-gate ERE
  numeric boundary + `source=sighup` + serial sanitizer.

### Known transient infrastructure flake

Post-merge CI on docs-only commits has occasionally failed only the
`openwrt e2e` job with `daemon not ready (no NFQUEUE bound)` — cold QEMU
TCG boot exceeding the 300s wait under loaded shared runners. It is an
environment/timing flake, not a code regression; reruns on identical code
pass. Contains no code change — still relevant to v0.2.2 CI.

## Compatibility and upgrade notes

- **Config additions are additive**: `offload_policy=enforce` and
  `allow_bypass` are new optional fields; existing v0.2.1 config/UCI
  files remain valid. `offload_policy=warn|refuse|readiness` behavior is
  unchanged.
- **Independently verified downgrade path**: `goshisen-boot disable`
  before downgrade; rescue `unlink` documented.
- Rollback behavior and boot-guard caveats from v0.2.1 notes are
  unchanged.

## Versioning / package decision

- CLI source version stays `"dev"`; tag `v0.2.2` stamps the binaries at
  build time (Makefile `VERSION ?= $(shell git describe --tags --always
  --dirty)`).
- **OpenWrt package: `PKG_VERSION=0.2.0`, `PKG_RELEASE=4`, daemon source
  pin `f5f211a173dab2934a42e3aa8220ab2d54fa12da` — unchanged at the
  candidate.** Building the package from the candidate tree would include
  the updated package recipe (prerm unconditional rc.d link removal via
  `goshisen-lifecycle.sh`, `allow_bypass` UCI YAML rendering, init
  fixes) but the **daemon binary** inside the `.apk` ships from the
  pinned `f5f211a` source: boot-guard + offload warn/refuse/readiness
  only. It does NOT contain the v0.2.2 daemon changes (enforce-mode
  offload disable, flowtable observability, signing/provenance) nor the
  v0.2.1+ daemon fixes. This follows the project policy of versioning
  the OpenWrt package independently of the CLI release; it is a
  documented gap, not a release blocker. If the v0.2.2 daemon features
  must be installable on OpenWrt, a separate package source-pin bump +
  SDK rebuild/validation task is required (out of scope for this
  release).
