## What this release is

v0.2.2 is a test-infrastructure + reliability release. It contains no
policy-engine, packet-path, or firewall-behavior changes: the only binary
change is a shutdown-readiness race fix in `internal/app`. Everything
else is the reproducible privileged e2e harness, the hermetic preflight
abstraction, environment diagnostics, and documentation.

The rule from the v0.2.1 audit stands: `main` after tag `v0.2.1` must
not be published under the v0.2.1 name; this release is the vehicle for
it.

## Highlights

- **Reproducible privileged NFQUEUE e2e runner** (`scripts/e2e-runner.sh`):
  one entrypoint runs the same path in CI and on a local privileged lab —
  typed preflight → environment manifest → pinned-image provisioning →
  boot → e2e → trap teardown → failure artifacts. Exit codes 0/1/3
  (ENV)/4 (PROVISION)/5 (BOOT); `E2E_PREFLIGHT_ONLY=1` stops after READY.
- **Hermetic preflight fixtures**: the preflight gates consume an injected
  environment view (`real_env` or fixture file `E2E_PREFLIGHT_FIXTURE`);
  unit tests run without touching the host (no qemu/nft/ip/sudo).
- **Environment manifest + diagnostics** (`scripts/e2e-env-manifest.sh`):
  OS/kernel/arch, tool versions, module state, commit, timestamp — written
  *before* preflight so blocked runs still record the environment; failure
  artifacts (serial/daemon log, nft state, routes, processes, modules)
  collected on failure.
- **Readiness shutdown race fix** (`internal/app`): `ready` is now cleared
  on every exit path (`defer d.ready.Store(false)`), fixing a race where a
  fast shutdown could leave `ready=true` after `Run` returned.
- **Lab hardening** (`scripts/openwrt-lab.sh`): stale-pidfile detection
  (cmdline must carry the lab TAP), pre-clean of stale netns/tap/bridge/
  veth, `down` kills every lab QEMU and removes VETH too.
- **Lab port gate 5555/2222 only**: preflight RESOURCE gate checks exactly
  the lab ports (serial console + SSH forward); a foreign server on 8088
  can no longer produce a false RESOURCE.
- **e2e reload-gate fix** (`scripts/openwrt-e2e.sh`): gate ERE now has a
  numeric boundary (`rules=N([^0-9]|$)`), requires `source=sighup`, and the
  serial sanitizer maps non-printable bytes to `?` instead of keeping raw
  high bytes (garbled-UTF-8 transcripts no longer time out the gate).

### Known transient infrastructure flake

Post-merge CI on docs-only commits has occasionally failed only the
`openwrt e2e` job with `daemon not ready (no NFQUEUE bound)` — the cold
QEMU TCG boot exceeding the 300s wait under loaded shared runners. It is
an environment/timing flake, not a code regression; reruns on identical
code pass. **Contains no code change** — still relevant to v0.2.2 CI.

## Compatibility and upgrade notes

- **No config changes.** v0.2.1 config files, UCI settings, and policy
  YAML are compatible as-is.
- **No OpenWrt package change in this release** — see the versioning
  decision below. The OpenWrt package's version is independent of the
  release tag; pulling this release into the package (if desired) would
  be a separate package-version bump with its own SDK validation.
- Rollback behavior and the boot-guard downgrade caveat documented in the
  v0.2.1 notes are unchanged.

## Versioning / package decision

- CLI source version stays `"dev"` and is link-time stamped
  (`make`/`scripts/package.sh`; Makefile `VERSION ?= $(shell git describe
  --tags --always --dirty)`). The release tag `v0.2.2` will stamp the
  binaries at build time.
- **OpenWrt package version is NOT bumped in this release.**
  `openwrt/Makefile` keeps `PKG_VERSION=0.2.0`, `PKG_RELEASE=4`. Reason:
  the project's policy treats the OpenWrt package version as independent
  of the CLI release version (the package is versioned by its own
  SDK-verified source pin/mirror hash); v0.2.2 contains no package or
  firmware-facing behavior change that would justify a package bump. If a
  future release changes the installed daemon behavior, the package would
  be re-validated and versioned separately (the previous releases used
  PKG_VERSION=0.2.0 with PKG_RELEASE increments for the package line).
