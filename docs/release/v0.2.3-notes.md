# GoShiSen-Enforce v0.2.3 — Release Notes (draft)

**Status:** draft for v0.2.3. **Date:** 2026-11-15.
**This is a packaging/signing release: no runtime source change since
v0.2.2.**

## What is in v0.2.3

- First release whose OpenWrt package (`0.2.3-r1`) is **production-signed**
  (apk v3 embedded signature, anchor
  `keys/goshisen-apk.pub.pem`, fingerprint
  `542bb7ae9058fee9b4d37ed30b0af44f234ea7cb8866daa1ffc71a7bc37c839d`).
  Previous published APK (v0.2.0's `0.2.0-r2`) was **unsigned**;
  v0.2.1 and v0.2.2 published no APK asset.
- CLI release again signs archives with the production Ed25519 key
  (signatures + provenance + SBOM), as v0.2.2.
- Package daemon stamp reports `0.2.3` (package version); the runtime
  source is identical to v0.2.2 (`c5de6e8`) — same source, different
  stamp. `git diff c5de6e8 v0.2.3 -- internal cmd pkg go.mod go.sum`
  is empty (verified before release).
- The CLI release key (`GH_RELEASE_SIGNING_KEY`) and the APK signing key
  (`GH_RELEASE_APK_SIGNING_KEY`) are different and never interchanged.

## Verifying and installing the signed package

APK public trust anchor (full SHA-256 of DER SPKI):
`542bb7ae9058fee9b4d37ed30b0af44f234ea7cb8866daa1ffc71a7bc37c839d`.
Cross-check this fingerprint from a second source (e.g. the repository
`keys/goshisen-apk.pub.pem` + the custody record in
`docs/release/apk-signing-key-custody.md`).

Install the anchor into the OpenWrt trust store and install the package
**without** `--allow-untrusted`:

```sh
# on the router/VM (as root)
mkdir -p /etc/apk/keys
# fetch the anchor (or copy from a trusted medium)
wget -O /etc/apk/keys/goshisen-apk.pub.pem \
  https://raw.githubusercontent.com/88kbleirad/GoShiSen-Enforce/v0.2.3/keys/goshisen-apk.pub.pem
openssl pkey -pubin -in /etc/apk/keys/goshisen-apk.pub.pem -outform DER | sha256sum
# must print: 542bb7ae9058fee9b4d37ed30b0af44f234ea7cb8866daa1ffc71a7bc37c839d

# verify the package signature with apk (expected: OK)
apk verify --keys-dir /etc/apk/keys /path/to/goshisen-0.2.3-r1.apk

# install (signature verified by apk; no --allow-untrusted)
apk add /path/to/goshisen-0.2.3-r1.apk

# check the installed binary + its checksum
apk list --installed | grep goshisen
sha256sum /usr/sbin/goshisen
/usr/sbin/goshisen --version   # => goshisen 0.2.3
```

The release's `checksums.txt` lists the apk's sha256; verify it against
the downloaded file. The gate's provenance manifest records the apk
sha256 produced at signing time.

## Known limitations

- **Stateful IPv6 (issue #5):** stateful IPv6 ACCEPT relies on kernel
  conntrack CT-attribute delivery; when unavailable, affected traffic is
  INVALID → DROP (fail-closed). Stateless IPv6 ACCEPT is verified.
- **Other architectures (issue #7):** x86_64 and aarch64 (armsr/armv8,
  QEMU TCG) are verified; other OpenWrt targets are untested.
- **LuCI (issue #8):** a LuCI frontend is proposed (design doc) but not
  implemented.
- **Package pin vs release tag (issue #9):** the package pins the daemon
  source SHA (`c5de6e8`, v0.2.2) rather than the tag itself — deliberate
  (self-referential pin avoided); see the v0.2.3 proposal.
- The daemon binary's `--version` prints `0.2.3` (no `-r1` suffix; the
  package release suffix is an apk concept).
- QEMU TCG emulation only for aarch64 (no physical hardware claim);
  flowtable offload hit counters are TCG-zero (bypass impact not
  observable in the lab).
