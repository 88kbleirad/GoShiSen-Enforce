## Update (2026-11-17)

Post-publish hardening for v0.2.5 (no changes to release assets; all
verification performed against the published v0.2.5 set):

- **Signed-tag gate** (`scripts/release-pin-gate.sh` step 6, PR #70,
  v0.2.6+): the release gate now verifies the release tag is signed by
  a key in `docs/trust/allowed_signers` when `GATE_TAG_SIGN_CHECK=1`
  (opt-in; off by default until a signing key is configured). Unsigned
  historic tags (v0.2.3–v0.2.5) do NOT fail when the check is off.
  Tests cover signed-tag pass, unsigned-tag fail (enforcement on), and
  forged/wrong-key fail.
- **Full release-asset verification** (`scripts/verify-release-assets.sh`,
  PR #70): one fail-closed pass over all 19 CLI assets + the signed apk;
  apk sha256 now verified via `apk verify --sha256` against the anchor.
- **Arm64 runtime evidence** (`docs/release/arm64-v025-runtime-evidence.md`):
  the public `goshisen-linux-arm64.tar.gz` v0.2.5 asset (binary sha256
  `715ec1c9…`, matches `checksums.txt` was executed under QEMU aarch64
  TCG: policy controls, SIGHUP reload, queue binds, offload-enforce
  disable, post-enforce DROP all PASS. This is EMULATION, not hardware;
  flowtable hit counters are zero-hit under TCG, so offload behavior on
  physical arm64 remains unverified (issue #7 stays open).
