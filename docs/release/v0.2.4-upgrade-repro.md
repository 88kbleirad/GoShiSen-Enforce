## Post-upgrade script content (from /lib/apk/db/scripts.tar.gz)

```
#!/bin/sh
export PKG_UPGRADE=1
[ "${IPKG_NO_SCRIPT}" = "1" ] && exit 0
[ -s ${IPKG_INSTROOT}/lib/functions.sh ] || exit 0
. ${IPKG_INSTROOT}/lib/functions.sh
export root="${IPKG_INSTROOT}"
export pkgname="goshisen"
add_group_and_user
default_postinst
	if [ -z "${IPKG_INSTROOT}" ]; then
		/etc/init.d/goshisen enabled || true
		[ -x /etc/init.d/goshisen-boot ] && /etc/init.d/goshisen-boot enable || true
	fi
```

`default_postinst` (base-files functions.sh) loops the package filelist's
init.d entries calling `start` on each. `goshisen-boot start` re-adds the
fail-closed chain → fails (daemon's chain has different declaration).
`goshisen start` via rc.common procd path registers the same
instance/params → procd does not restart the running process.

## Manual restart (documented remedy)

`/etc/init.d/goshisen restart` → new pid 4448, `/proc/4448/exe` =
`/usr/sbin/goshisen` sha `1feebeba...` (v0.2.4), hook re-installed,
queue 100 bound peer 4448. Probes during restart: 17/17 = 000
(60-iteration loop ran through 03:25:42; restart at 03:29:36 — the loop
had ended; 3 additional deny probes after restart = 000).

## Positive control on new binary

Allow policy + HUP (rules=2) → allow-post1/2 = HTTP 200.

## Verdict (Item 1c)

- **NO unprotected/unqueued window observed**: 0/60 deny probes passed
  during upgrade and 0 passes across restart; the queue rule persists in
  the kernel while the old process keeps the listener, and after
  `restart` the new daemon reinstalls the hook before/at bind.
  Fail-closed invariant held.
- The defect is operational: an `apk upgrade` does NOT switch the
  running daemon to the new binary. The running process references the
  deleted old inode until a manual restart. This is the class-2 bug
  (version skew after upgrade), not a security hole — but must be fixed
  so upgrade delivers the new binary automatically.
