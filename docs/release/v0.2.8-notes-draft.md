# GoShiSen-Enforce v0.2.8 — Release Notes (DRAFT)

> **STATUS: DRAFT — not published.** Working notes for the next release
> after the published v0.2.7 (2026-11-21). Becomes the release body only
> after the maintainer publishes the tag. Nothing here is published yet.

**Planned type:** security/hardening release — bounded file reads,
authenticated-API opt-ins (D1), OpenWrt token file hygiene, and CI
gate re-balancing (D2). Toolchain: go1.27.4 (unchanged).

## What is new since v0.2.7 (runtime changes)

1. **Bounded file reads (`internal/safefile.ReadBounded`, PR #104).**
   `os.ReadFile` on a non-EOF stream (a character device such as
   `/dev/urandom`, or a FIFO) never returned and grew memory without
   bound — measured ~1 GiB/s RSS in the anomaly sweep; a policy path
   pointing at such a file hung the daemon/CLI before processing
   began. The new reader rejects non-regular files **without
   blocking** (O_NONBLOCK open + descriptor validation, PR #112) and
   caps reads at 16 MiB. Applied at every operator-input read:
   config file, CLI `--policy-file`, daemon policy load and SIGHUP
   reload, and the policy store (`active.json`, version files).
   Severity assessment: local DoS / CI-hang only — the file is
   operator-supplied and local, so there is no remote vector; the
   hang would affect a misconfigured deployment, not an attacker.
2. **OpenWrt UCI `api_token` (PR #108).** The packaged config can now
   set `api_token`; the init script renders it into the daemon config
   and creates/keeps the sensitive files (rendered config and the UCI
   file itself) at mode 0600 from the first instant (PR #109). Token
   charset is restricted to `A-Za-z0-9._-`; a start with anything else
   aborts naming the option (fail-closed, never shell-evaluated).
3. **Authenticated-read opt-ins, D1 (PR #110, issue #99).** New
   options `require_token_for_reads` and `metrics_token_required`
   (config file / `GOSHISEN_REQUIRE_TOKEN_FOR_READS` /
   `GOSHISEN_METRICS_TOKEN_REQUIRED` / `--require-token-for-reads` /
   `--metrics-token-required` / UCI). With an `api_token` configured:
   - `require_token_for_reads` → `GET /v1/policy` and
     `GET /v1/policy/versions` require the bearer token;
   - `metrics_token_required` → `GET /metrics` requires it;
   - `/healthz` and `/readyz` always stay open;
   - both default **off** (historical behavior unchanged), and setting
     either without a token is a configuration error.
   **Compatibility:** enabling `require_token_for_reads` breaks
   clients that read `/v1/policy` without a token — add
   `Authorization: Bearer …` first.

## Upgrade items (what changes for an operator)

- **Misconfigured paths now fail fast instead of hanging.** Bounded reads apply
  to the config file, `--policy-file`, the daemon's policy load and SIGHUP
  reload, the policy store (`active.json`, version files), the queue-stats
  procfs read and the startup validation of `policy_file`: a non-regular file
  (FIFO, device, directory) or a file over the 16 MiB cap is rejected with a
  clear error instead of blocking forever (previously a FIFO path blocked
  startup and `/dev/urandom` grew ~1 GiB/s).
- **Authenticated reads are opt-in (D1), default off.** With an `api_token`
  configured, `require_token_for_reads` makes `GET /v1/policy` and
  `GET /v1/policy/versions` require `Authorization: Bearer ...`, and
  `metrics_token_required` does the same for `GET /metrics`. `/healthz` and
  `/readyz` always stay open. Enabling either **breaks** clients that read
  those endpoints unauthenticated — update them first. Setting either without a
  token is a configuration error.
- **OpenWrt: `api_token` via UCI, sensitive files 0600.** The packaged config
  can set `api_token`; the rendered daemon config and the UCI file are created
  mode **0600** from the first write. The token charset is restricted to
  `A-Za-z0-9._-` — anything else aborts the start naming the option
  (fail-closed; the value is never shell-evaluated).
- **No listener-default change in v0.2.8.** The semantics introduced in v0.2.7
  still hold: an **explicit** `api_port`/`metrics_port: 0` **disables** that
  listener; an **unset** value keeps the defaults (API `127.0.0.1:8080`,
  metrics `127.0.0.1:9090`). If you upgraded from ≤ v0.2.6 and rely on
  `127.0.0.1:9090/metrics`, set the port explicitly (v0.2.7 note repeated here).
- **Signing posture:** the CLI release key is repository-scoped and signing is
  not approval-gated (F-02 withdrawn, #125); release tags are annotated but
  **unsigned**.

## What changed in CI/tooling (not runtime)

4. **Govulncheck is now advisory on PRs, blocking in releases (D2,
   PR #111).** The `robustness` CI job reports findings as a warning +
   step summary (never fails a PR). The blocking gates stay:
   `release.yml` S-005 binary-mode gates, `apk-sign.yml` payload gate,
   and `release-pin-gate.sh --tag … GATE_S005_CHECKS=1`.
5. **Weekly security sweep (`.github/workflows/security-weekly.yml`).**
   Mondays 06:17 UTC plus `workflow_dispatch`; runs govulncheck
   (source), staticcheck and gosec (pinned); on findings opens one
   deduplicated `[security-scan]` issue (appends to the open one).

## Limits and unverified areas

- **arm64** still verified only under QEMU TCG (no hardware).
- The D1 change is exercised by unit/integration tests and the CI
  matrix; it has not been run on a live OpenWrt router yet.
- The UCI token-file mode behavior (0600) was verified on a fresh
  OpenWrt 25.12.6 x86/64 guest; `uci commit` preserves the mode, but
  a buggy `uci` tool could reset it — the rendered `/var/run` config
  (0600) is the source of truth.
- Signed tags: `docs/trust/allowed_signers` **is** committed (SSH trust anchor), but tag signing is **not enabled for this release** — `v0.2.8` will be an annotated, **unsigned** tag and the pin gate's signature check stays opt-in (`GATE_TAG_SIGN_CHECK` is not set in CI).
- **F-02 posture (changed during v0.2.8):** the CLI signing key is **repository-scoped** and signing is **not approval-gated** — the `release-cli` environment gate was implemented and then withdrawn in #125 after the environment was deleted. `release.yml` no longer declares an `environment`; the F-02 guard still confines the key to the `sign` job. Reinstating the approval gate needs the key's value in an environment secret (the offline file or a key rotation) — see `docs/release/f02-environment-migration.md`.
