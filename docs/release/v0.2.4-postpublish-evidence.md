## Fresh-VM upgrade test (v0.2.3 → v0.2.4, continuous probes)

Environment: clean stock OpenWrt 25.12.6 image, lab topology, anchor
installed, kmods installed, allow policy (8089) loaded on v0.2.3.

1. Install v0.2.3 (public `948e2e1d...`): `apk add --no-network` OK,
   `--version` = goshisen 0.2.3, daemon up (hook + queue 100 bound).
2. Continuous probes from LAN client (3s timeout, every 2s):
   - 35/35 = 200 before/through the `apk add v0.2.4` install — **no
     fail-open window**.
3. `apk add --no-network /tmp/new.apk` (v0.2.4): `Installing
   goshisen-0.2.4-r1`, OK. The init script's restart during post-upgrade
   hit `Chain "forward" already exists` (old daemon still holding the
   table — benign); a manual `/etc/init.d/goshisen restart` loaded the
   new binary cleanly.
4. During/after restart, probe loop 2: **30/30 = 200** — no fail-open.
5. Post-restart state: `goshisen 0.2.4`, queue 100 bound to new pid
   (320 packets), policy rules=2 preserved across upgrade.
6. Negative (anchor removed): `apk verify` → `UNTRUSTED signature`,
   rc=1. Anchor restored.
